## 集中题目

1. 现存定位脚本为什么保存一份屏幕点，再查命中/根对象？HWND、坐标、标题、PID 分别是什么，保存句柄会延长窗口生命周期吗？
2. 内容区与标题栏命中相同句柄是否意味着代码错误？`GA_ROOT` 与 `GA_ROOTOWNER` 的关系、参数来源和应用边界是什么？
3. `WindowFromPoint`、`GetWindowText` 的 Python 调用与微软 C 文档为什么看上去参数个数不同？空句柄、空标题、调用异常为什么要分开处理？
4. 如果原始点没变但识别对象变了，你会怎样定位？当前脚本窗口查询之间目标消失的风险是否已经复现/修复，怎样给出诚实的验证计划？

## 参考答案：统一核对

**1**：保存一次点使同一组查询对应同一个观察起点，避免每取属性又读取移动后的鼠标。坐标是空间位置，HWND 是窗口不透明引用，标题是可变属性，PID 是进程标识；它们不能互相替代。同一进程可有多个窗口，句柄数值保存不会阻止窗口销毁或复用。项目将来应使用点击当时的数据；当前延时采样只验证定位，不是已经实现点选。

**2**：不一定错误：界面元素可能是自绘而无独立子 HWND，也可能已直接命中顶层。GA_ROOT 沿父链找根，GA_ROOTOWNER 还考虑 owner 关系，可能得到另一个顶层对象；`2` 是前者常量，无时间单位，不是“走两层”。用同一窗口两处、两个同时存在窗口对照，不为了符合教材强求差异。对话框、特殊界面与多屏条件没有测过就说明限制。

**3**：pywin32 封装了部分类型转换与输出缓冲区。WindowFromPoint 接收一个整数坐标元组，GetWindowText 接收 HWND 并直接返回字符串，不照搬 C 指针参数。空句柄意味着没有后续有效查询对象，空标题可能是正常属性值，异常意味着调用失败需保留原 API 与原因。项目不能用一个布尔判断把三者混同，也不能异常后拼上上一轮信息。依据：[包装文档](https://mhammond.github.io/pywin32/win32gui__WindowFromPoint_meth.html)、[GetWindowText](https://mhammond.github.io/pywin32/win32gui__GetWindowText_meth.html)。

**4**：先检查采样时机、鼠标/窗口移动、覆盖关系、标签与变量是否混用，再看根查询和坐标空间。点对应的是当时桌面，不永久绑定窗口；连续跨进程查询也不是原子快照。当前只能从源码看出未捕获相应查询异常，不能声称用户已遇到并修复。验证先用稳定对象建立基线，再在可控目标消失场景保留失败调用/回溯；用户做局部修改后复测正常与失败路径，记录实际结果。

**5**：源码证明存在某种实现，静态语法只证明可解析；实机输出和测试条件才支撑功能结论。参考过答案要说明范围，指出自己的设计/修改/验证与能解释的机制，不因两个文件相同就推断作者，也不隐去 AI 参与。本地 commit 是版本证据，push 是远程同步，都不自动验证程序。完整成品还需要 GUI、输入/取消/过滤/恢复、独立构建与安装/卸载证据；面试讲真实已发生的成长、尝试与限制，不讲计划如同成果。
