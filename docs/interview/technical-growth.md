## 一次真实突破怎样记录

只对重要变化展开，不要求每天填满所有字段：

```text
ID / 日期 / 技术与当前功能：
工程成果：功能、源码、运行测试与实际 Git 证据：
学习成果：真正的新技术及本人的实验、参数/流程分析：
五层说明：是什么 / 为什么 / 怎么工作 / 怎么使用 / 应用与改进：
1. 最初遇到的问题或缺口：
2. 为什么软件当前需要它：
3. 实际学习资料及关键收获：
4. 我真的尝试过哪些方案（没有就写未比较）：
5. 最终采用方法 / 状态（五类之一）：
6. 为什么有效，适用范围和局限：
7. 源码、实际输出/测试、Git 提交等证据：
8. 面试深入追问时能解释什么、还不懂什么：
本人独立设计/修改/验证部分 / 参考或 AI 辅助范围：
掌握链核对：原理→独立编写→实际测试→排查问题/边界分析→能够讲解；缺哪环：
```

“读过教程”“写了代码”“运行通过”“独立解释”“别人环境可用”是不同证据等级。尚无结果用待验证，不以计划中的成果补齐空白。下一条优先补 G02 的三组实测，再按 [双模式契约](../interaction-modes.md) 记录普通请求、强制进程/权限等实际进展，而非另造与项目无关的练习。10-27 确认双模式和管理员启动只算需求变更，不能记作用户已掌握或工程已通过。
