## 目标职责（设计方向，尚未实现）

| 职责 | 需要明确的输入/输出与拥有权 | 未来界面/系统关系 |
|---|---|---|
| 输入适配 | 复制必要的事件时刻数据，短回调；明确 listener/hook 的拥有者和退出责任 | 接收外部应用点选，不直接操作 GUI 控件 |
| 识别与目标信息 | 点位→当次候选事实或失败；不长期缓存旧句柄 | 复用当前已写查询知识，状态区可展示核对信息 |
| 允许/拒绝判定 | 两策略排除自身/桌面/任务栏/未知目标；强制额外核对进程身份并排除外壳/关键/受保护对象 | 拒绝本次动作后会话继续；自身 GUI 与进程级过滤分别验证 |
| 清理会话与动作协调 | 开始时固定策略/会话，右键每次最多一次操作；左键放行，Esc 退出；去重、配对、拒绝旧事件 | 单次动作完成不结束会话；空闲才能切换策略，核心接线由用户手写 |
| 普通执行 | 对当次允许 HWND 投递 WM_CLOSE，返回投递事实/错误 | 目标可提示/取消；普通失败不自动升级强制，目标反应另观察 |
| 强制执行 | 核对窗口所属 PID 与当次进程句柄，发起终止，确认退出/超时，释放持有句柄 | 同 PID 多窗口可能受影响；不按名字批杀/递归子进程；等待不阻塞 GUI/输入回调 |
| GUI 与反馈 | 普通/强制选择、默认普通、当前模式/风险/操作结果，主线程接收后台通知 | 两模式左键正常，普通可操作确认框；跨应用光标与退出恢复实测 |
| 权限、构建与安装 | 应用请求管理员权限，收集依赖/资源与版本；UAC 拒绝路径 | 应用 manifest/调试进程/安装器权限分别核对；PyInstaller→Inno 安装及快捷方式启动各自验收 |

这里只定义需要解决的职责，不指定尚不存在的函数/类/文件，不把每项职责强行拆成一个文件。用户根据实际实现决定组织，代码审查检查依赖方向、状态拥有者、异常与资源生命周期。

## 需要在实现中回答的架构问题

- 谁拥有会话策略和接纳每次动作的权限，谁只展示？如何去重同一右键/处理中进程，如何拒绝旧会话事件？Esc 与尚未接纳动作如何定序，为什么不能撤销已发起操作？
- HWND→PID→进程句柄的身份核对、最小访问权和释放由谁负责？强制调用与确认退出怎样分别反馈，普通失败如何保证不自动升级？
- 哪个线程可以调用 GUI，哪个地方可以等待，怎样完成正常/异常退出？
- 句柄/事件属于哪一次观察或哪一轮？对象变化如何拒绝，哪些检查不能消除系统外部竞态？
- 安装版运行时资源、配置/日志与程序文件放在哪里，卸载哪些、保留哪些？到真实采用时再记录，不提前编造实现路径。
