### 新函数先讲清：创建队列、放入与取出

`events` 是我们给变量起的名字；它引用一个 `queue.Queue` 对象。`put_nowait` 和 `get` 是这个对象提供的方法，必须先创建对象，再通过 `events.方法(...)` 使用。下面只讲本次新接口，不重学已有语法。

**① `events = queue.Queue()`：创建保存事件的队列。** 导入 `import queue`，准确构造形式是 `queue.Queue(maxsize=0)`；省略参数就是 `maxsize=0`，表示不设置条数上限，不是容量为零。构造返回队列对象，先放入的记录先被取出（FIFO）。例如先放 A 再放 B，连续取两次就依次得到 A、B。它内部同步保护多个线程的放入/取出；普通列表不会自动提供这里的等待/超时接口，所以本课用队列连接回调和主线程。

**② `events.put_nowait(item)`：放入一条数据，不等待空位。** `item` 是唯一参数，可以是本次使用的元组；成功返回 `None`，并不返回这条记录。`nowait` 的准确含义是“不等待队列腾出空位”：如果给队列设置了容量且已满，就立即抛 `queue.Full`，不是返回 False，也不是静默丢掉旧记录。当前默认队列没有条数上限，所以正常使用不会因“已满”走这个分支；但生产太快仍会积压。内部同步仍可能有短暂等待，不能理解为绝对零耗时。

对照参考中的这一句：

```python
events.put_nowait(("click", (x, y, button, pressed)))
```

整个元组是一条记录、一个 `item`：第一项 `"click"` 是我们自己约定的事件种类，第二项是点击数据。`"click"` 不是库规定的字符串；`("exit", None)` 同样是我们自定义的退出通知，None 表示这类通知不需要额外数据。**放入队列只保存记录，不调用识别或关闭函数，也不自动执行通知所描述的操作。** 为什么在回调里这样用：回调尽快交出数据，主线程之后再处理；不选可能等待空位的默认 `put(item)`，避免日后加容量限制时让输入回调一直等队列。

**③ `kind, payload = events.get(timeout=0.1)`：取走最早的一条记录。** `get` 属于同一个队列对象；`timeout=0.1` 表示队列暂时为空时最多等待约 0.1 **秒**，有记录则可立即取出，不是每次都固定暂停 0.1 秒。成功返回那条 `item`，同时把它从队列移除；取出 `("click", (100, 200, ...))` 后，`kind` 就是 `"click"`，`payload` 是后面的点击数据。`payload` 只是我们起的变量名，不是另一个库接口。取出不等于后面的识别业务已经完成。

**④ `except queue.Empty:`：处理“等了一会仍没数据”。** `Empty` 是队列模块定义的异常类型，不是检测队列的函数，也不用写括号调用。`get(timeout=0.1)` 等到期限仍没有记录就抛它，而不是返回 None；本例用 `continue` 回到 while，重新检查实验期限和线程状态。默认 `get()` 在空队列上会一直等到有记录，可能让主线程没机会检查退出，因此这里明确给超时。`queue.Full` 对应放不进去，`queue.Empty` 对应取不到，不能混用。

先运行这个**不启动监听、不操作窗口**的小例子，理解队列状态变化即可，不增加一套必做练习：

```python
import queue

mailbox = queue.Queue(maxsize=1)  # 故意限制为一条，便于看到满/空。
result = mailbox.put_nowait(("click", (100, 200)))
print(result)  # None；记录已经放进去了。

try:
    mailbox.put_nowait(("exit", None))  # 第一条还没取走，队列已满。
except queue.Full:
    print("满了，第二条没有放入")

print(mailbox.get(timeout=0.1))  # ('click', (100, 200))；取完后为空。
try:
    mailbox.get(timeout=0.1)  # 约等 0.1 秒仍为空。
except queue.Empty:
    print("空了，这次没有取到")
```

预期依次输出 `None`、`满了，第二条没有放入`、`('click', (100, 200))`、`空了，这次没有取到`。这里用容量 1 只是展示错误契约，**不是让你把正式输入队列直接改成容量 1**；实际若限容量，还得设计满时的退出/配对处理。Python 3.15 还有主动关闭队列后的 `queue.ShutDown` 契约，本例未调用关闭队列接口，当前不引入该分支。[官方 Queue 与异常契约](https://docs.python.org/3/library/queue.html)

### 其余新接口：创建监听、计时与退出

**`mouse.Listener(on_click=on_click, suppress=False)`** 来自 `pynput.mouse`，创建并返回鼠标监听对象。`on_click=` 左边是库规定的参数名，右边是我们定义的回调函数；你也可以把函数取名为 `record_click` 再写 `on_click=record_click`。库收到点击时传入 `x/y`（事件时刻的屏幕坐标）、`button`（按键枚举）、`pressed`（True 按下、False 松开）。`suppress=False` 明确不全局阻止输入。只构造还不会开始监听。

**`keyboard.Listener(on_release=on_release, suppress=False)`** 同理创建键盘监听对象；`on_release` 指定松开键时调用的函数，库给它一个 `key` 参数。`keyboard.Key.esc` 是库提供的 Esc 枚举成员，用来与 `key` 比较；不是字符串 `"esc"`，也不是我们定义的函数。本例只为 Esc 松开发送退出记录，其他键不记录。

**`listener.start()`** 属于监听对象，无参，正常返回 None，发起后台监听后主线程继续向下执行；不会替主线程维持当前业务循环，也不证明已经收到了事件。对同一个线程实例再次启动会报错，停止后重做实验应新建对象。**`listener.stop()`** 同样无参、正常返回 None，只请求该监听停止；鼠标对象不会顺便停止键盘对象，所以两者分别调用。

**`listener.join(timeout=1.0)`** 在调用它的线程中等待该监听线程退出；1.0 的单位是秒，是本次允许等待的窗口。已经退出则可以立即返回，到期仍未结束也返回 None；所以不能 `if listener.join(...):` 判断退出成功。回调抛出的异常还可能经这里重新抛出。**`listener.is_alive()`** 无参，返回线程是否存活的 True/False，用在 join 后核对，正常收尾应为 False；它不证明回调成功处理了点击。这里的 join 是 listener 的方法，本日没有使用队列的同名方法。

**`time.monotonic()`** 来自标准库 time，无参，返回单调时钟的浮点秒数；起点没有日期含义，不能拿它当北京时间。本例假设第一次返回 100.0，`deadline = 100.0 + 15` 就是 115.0；以后每轮比较当前值是否小于 115.0。系统校时不会让这个时钟倒退，适合算持续时间。实际起点由系统决定，上面的数只是帮助理解的假设，不是运行观察。它不创建定时器、也不自动停止监听，是否结束仍由 while 和 finally 执行。

`RuntimeError("...")` 是内置异常，本例用 `raise` 在检测到监听线程提前结束时报告原因；`KeyboardInterrupt` 是终端 Ctrl+C 通常引发的内置异常。两者都与“队列暂时没数据”的 `queue.Empty` 不同，不应该全部吞掉后假装实验成功。

### 函数速查：上面讲过后再回看

| 函数/模块 | 参数、返回、错误和边界 |
|---|---|
| `mouse.Listener(on_click=on_click, suppress=False)` | 回调 `(x, y, button, pressed)`；构造得到 listener，还未运行。坐标是事件时刻的屏幕点；`button` 与 `mouse.Button.right` 等枚举比较；`pressed` 是布尔值 |
| `keyboard.Listener(on_release=on_release, suppress=False)` | 回调收到 `key`，本例只比较 `keyboard.Key.esc`；普通键不一定具备特殊键属性。不记录其他键内容 |
| `listener.start()` / `stop()` | 无参，正常返回 `None`；分别启动后台线程/请求停止。停止实例不能再次 start，重复实验新建实例 |
| `listener.join(timeout=1.0)` | 主线程等退出，单位秒，正常返回 `None`；可重新抛出回调异常。不能在该 listener 的回调里等待自己 |
| `listener.is_alive()` | 无参，返回线程存活布尔值；join 超时后用它核对，线程活着也不证明事件已收到 |
| `queue.Queue()` / `events.put_nowait(item)` | 默认不设容量上限；入队正常返回 `None`。不等待空位不代表无内部锁/硬实时；本例只存点击，不能照搬为无限收集所有移动事件 |
| `events.get(timeout=0.1)` | 返回并移除一条事件，0.1 的单位是秒；无事件到期抛 `queue.Empty`。这不是鼠标采样间隔 |
| `time.monotonic()` | 返回单调时钟秒数，只有差值有意义；本例 `15` 秒观察期是人为调试选择，可调整，不是协议常量 |

示例采用文档中的四参数鼠标回调。本机 1.8.2 后端还提供 `injected` 参数，已核对本机 `_wrap` 会适配较少参数的回调，所以本例不用为了版本增加不需要的参数。这里只说明实际源码契约，不把导入成功当成监听实测。[pynput 鼠标文档](https://pynput.readthedocs.io/en/latest/mouse.html)

本任务导入 `import win32gui as w`、`import win32con`、`import pywintypes`，调用形式复用项目现有代码，如下表。官方原生契约见下面资料；原生 C 签名与 Python 包装的参数形式、返回和异常需要分别理解。

| 本任务所需调用 | 参数、返回与失败边界 |
|---|---|
| `w.WindowFromPoint((x, y))` | 传一个包含屏幕坐标的二元组，返回命中窗口 HWND；无目标可能为 0。不要写成两个位置参数；失效或调用失败按实际返回/异常处理 |

现在先记住三种不同契约，不急着同时实现：

| 用法 | 实际作用 |
|---|---|
| 普通 `on_click` 回调 `return False` | 停止该 listener，不等于消费系统点击 |
| Windows `win32_event_filter(msg, data)` 返回 `False` | 隐藏后续普通回调，不等于阻止前台应用收到输入 |
| 在对应 filter 内 `listener.suppress_event()` | 消费当前系统输入；必要数据/通知先准备，不能等主线程取到队列后再补拦截 |

## 8. 四道技术面试题与就近答案

**1. 会 Python 函数，为什么输入监听仍是新技术？注册回调时为什么不加调用括号？**

参考答案：新知识是系统何时派发事件、由哪个线程执行及数据有效期。传函数对象是把未来的调用交给库；加括号会在当前位置先执行并传入返回值。项目需要用事件时刻的坐标，回调本身保持短，再通知消费者；这套机制可以迁移到 Go/Qt，语法变了机制仍在。

**2. 一次右键为什么打印两条？在 on_click 返回 False 能否阻止目标弹菜单？**

参考答案：按下与松开是两个事件，候选可以只在已约定阶段产生一次。普通回调 False 用于停止 listener，不是消费点击；Windows filter 的 False 与 suppress_event 也不是同义。产品要消费相应按下/松开并观察目标没有菜单；今天只做观察，弹菜单是预期，不是假称拦截失效的已复现 Bug。

**3. 为什么不在回调直接查询窗口，或等主线程处理时再读鼠标位置？**

参考答案：Windows 输入回调中的慢操作可能拖慢输入；把点击数据入队可缩短回调。后来读光标得到的不是原点击点；保存了点也不保证查询时原窗口仍在。队列传的是当时的数据，不保证窗口身份和会话状态。GUI 阶段还要由 GUI 线程更新控件，不能直接搬终端阻塞循环。

**4. stop、join、is_alive 分别说明什么？15、0.1、1.0 是什么？**

参考答案：stop 请求停止，join 等退出并可暴露回调异常，is_alive 核对当前存活；join 返回 None 不证明退出。15 秒是观察期限，0.1 秒是队列等待窗口，1.0 秒是每个线程的退出等待窗口，都是可调整工程选择；不代表输入采样周期或 API 常量。两个 listener 要分别收尾，停止实例不直接重启；超时/回调异常未解释就不能记完成。
