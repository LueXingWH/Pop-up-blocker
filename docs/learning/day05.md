### 沿着代码读必要原理

**`type Target struct { ... }`：把同次采集的数据组织起来。** `Target` 是我们声明的类型；`HWND`、`PID`、`Title` 是字段。`Target{HWND: 101, PID: 202, Title: "练习窗口"}` 创建一个记录，用 `target.PID` 取字段。相比位置元组，它明确各值的职责；它仍只是记录，不会自动查询 Windows。

`uintptr` 是可容纳指针位宽数值的无符号整数，本机为 64 位；`uint32` 固定 32 位，范围为 0～4294967295。本例用前者示意 HWND 的数值、后者示意 PID。它们不是同一种身份，不能因为都是整数就混用。**这不是已经选定的 Go Windows 绑定声明**；以后真正调用时要按所用绑定核对类型、返回与生命周期，不能把 `uintptr` 当会保持窗口存活的 Go 指针。

**零值**是没有显式填写时的默认值。`Target{}` 得到 HWND=0、PID=0、Title=""；所以“存在一个结构体变量”不等于“采集成功”。空标题可以来自普通窗口，本例保留空标题，不把它作为桌面判断。[Go 结构体与零值规范](https://go.dev/ref/spec#Struct_types)

**`makeTarget(hwnd uintptr, pid uint32, title string) (Target, error)`** 是参考自定义函数：前三项是输入，括号内两个类型是返回值。调用 `target, err := makeTarget(101, 202, "练习窗口")` 同时接住两项。Go 的多返回值不是把所有结果装进一个 Python 元组再交给调用者。`:=` 在函数内部声明并推导类型；后面同作用域给这两个变量重新赋值用 `=`。

**`error` 与 `nil`**：`error` 是 Go 内置接口，代表能提供 `Error() string` 的错误值；今天只需会接收、检查、输出，不要求先实现自定义接口。`nil` 在这里表示没有错误。`if err != nil` 是调用者必须主动做的检查；返回错误不会自动中断调用者。参考约定失败时返回 `Target{}, err`，成功时返回记录和 `nil`，这是本函数的契约，不能推断所有 Go 函数失败时第一返回值都必然是零值。[Go error 机制](https://go.dev/doc/effective_go#errors)

### 第一次用到的库函数，直接对照调用

| 准确调用 / 所属模块 | 参数、返回、失败及本次用途 | 最小变化 |
|---|---|---|
| `errors.New(text string) error`，`import "errors"` | 参数是错误文字，无单位；返回一个非 nil 错误值；不会抛异常、等待或结束程序。本例用固定文字解释哪个字段缺失 | `errors.New("缺少 PID")` → 调用者收到可打印的错误 |
| `fmt.Println(a ...any) (n int, err error)`，`import "fmt"` | 接收任意数量的输出值，以空格分隔并换行；返回写出的字节数与写出错误。参考把它当语句调用，不接这两项；这不等于输出永远不会失败 | `fmt.Println("记录失败：", err)` → 一行失败原因 |
| `makeTarget(hwnd, pid, title)`，本例自定义 | HWND/PID 没有时间单位；成功返回记录和 nil，字段缺失返回零值记录和错误；不做系统调用，也不锁定目标 | `(0, 202, "A")` → 零值记录与“缺少 HWND” |

API 依据：[errors.New](https://pkg.go.dev/errors#New)、[fmt.Println](https://pkg.go.dev/fmt#Println)。这里没有新线程、等待超时或需释放的 Windows 资源；返回的记录也不持有进程句柄。不要套用 Python `try/except` 去期待 `return ..., err` 自动触发异常。

## 7. 四道面试题，每题后紧接参考答案

**1. 为什么用结构体记录目标？HWND 和 PID 为什么不能合并成一个整数？**

参考答案：结构体把同次采集的不同职责字段放在一起，便于传递与定位数据来源。HWND 标识窗口，PID 标识进程，同一进程可能有多个窗口；二者都有生命周期与复用风险。`uintptr` 只是本例的数值表示，不是自动保活的指针。零值记录不代表采集成功；真实 Go 绑定还须单独核对原生类型和错误契约。

**2. `makeTarget` 返回错误，为什么后面的代码还可能继续运行？和 Python 异常有什么差别？**

参考答案：本例的错误是第二个普通返回值，调用者必须显式判断并决定退出或继续；没有自动抛出异常。Python `raise` 会沿异常传播路径寻找处理者，二者控制流不同。这里失败第一项按本函数约定为零值，忽略 err 继续判定会把无效数据当成候选；不能推断所有 Go API 都有同样的第一返回值契约。

**3. 记录字段完整、PID 不等于自己，就能按强制模式结束进程吗？**

参考答案：不能。这只通过两个练习条件，尚未验证真实窗口/进程身份、外壳/关键/受保护进程排除、执行前身份核对、权限、句柄释放及退出确认。字段齐备、允许操作、请求发起、实际退出是不同结果。普通模式也只请求 WM_CLOSE，不能因未关闭就升级强制；管理员权限不消除全部限制。今天没有执行这些产品操作。

**4. Python 只输出右键按下，为何不能证明右键被拦住？以后接 GUI 又有什么限制？**

参考答案：筛选的是自己的记录，`suppress=False` 仍把事件传给目标，右键菜单出现符合观察器行为。产品需选择性消费清理右键和退出操作，并正确配对；左键正常放行。回调只传数据，不能因用了队列就认为会话同步完成。Qt 阶段还要让 GUI 线程更新控件，不能把终端中阻塞的 get/while 原样塞进 GUI 主线程。
