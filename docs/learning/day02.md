### 坐标与窗口层级

屏幕坐标以主屏左上角为常用原点，主屏右/下方向值增大；左/上方扩展屏可能有负数。客户区坐标以对应窗口内部区域为基准，不能直接混传。今天沿用一个保存的屏幕点查询，不额外学坐标转换 API；将来接 Qt/输入回调时按实际空间重验，不凭缩放百分比猜乘除。

HWND 是系统引用窗口的不透明句柄，Python 以整数表示，不是可直接解引用地址，也不是 PID。窗口可能销毁且数值复用；保存整数不会延长生命周期。标题/类名可以相同、为空或改变，主要用于核对，不能单独认证身份。

一般 HANDLE 是其他多类 Windows 资源接口使用的句柄类型名称，HWND 有自己的窗口类型契约；原生类型可能用指针形态表示，但不等于调用者可读取目标内存。不同资源的查询/释放接口不能互换，不把释放一般句柄的方式套在别人的窗口上。

命中对象可能是子窗口；`GA_ROOT` 沿父窗口链取根，不沿所有者 owner 链无限归并。自绘界面并非每个视觉控件都有独立 HWND，所以同窗不同区域命中相同也可能合理。当前实验限定普通窗口，不把根查询策略当作所有对话框/特殊应用的通用关闭保证。

### 可选局部示例：保留异常，不掩盖失败

```python
try:
```

### 本任务原理：消息、异步投递与关闭结果

窗口程序处理 Windows 消息；`WM_CLOSE` 表达正常关闭意图，目标程序可提示保存、拒绝、关闭或保留会话。`PostMessage` 将消息放入目标相关线程的队列后返回，不等待处理完；成功只说明投递环节成功。

要能解释的不只是“异步”一词：调用者给出目标和消息，Windows 按该窗口的所属线程队列投递；目标线程取出并分发给窗口过程，目标程序决定如何处理关闭意图。Python 的 `queue.Queue`、Qt 事件循环与这里的原生消息队列是不同层次，不能混成一个队列；本课不要求自己写 Win32 消息循环，但下一课要能按一次真实请求说清谁投递、谁处理、哪一步尚未发生。[Microsoft 消息队列与分发](https://learn.microsoft.com/en-us/windows/win32/winmsg/using-messages-and-message-queues)

`SendMessage` 是同步发送，等待目标窗口过程处理，返回含义由消息决定，可能让调用线程等待；不是“一定更可靠地关闭”。本节为普通模式选异步投递。结束进程会影响同进程窗口/保存流程，属于独立强制模式，不作本节失败后备。`CloseWindow` 是最小化，不是正常关闭。

项目用 pywin32 复用已有环境和包装，省去自己声明 C ABI、字符串/缓冲区与错误转换的工作。`ctypes` 是可能的直接绑定替代，但当前没有包装缺口，不重复造两套。参数、返回和权限仍按每个 API 的契约理解，不因为有封装就忽略机制。

### 本任务用到的函数、常量与异常

| 调用/常量 | 参数与返回值 | 本任务作用与边界 |
|---|---|---|
| `win32gui.IsWindow(hwnd)` | 一个 HWND，返回非零/零 | 只看此刻存在，不锁住窗口，不能用它证明后续调用一定成功 |
| `win32gui.PostMessage(hwnd, message, wparam, lparam)` | 四项是目标、消息号及两消息特定参数；包装成功为 `None`，失败抛异常 | 本课只对当次核对的单一测试目标投递一次；不要按返回值真假判成功 |
| `win32con.WM_CLOSE` | `0x0010`，十进制 `16` | 协议消息号，无时间单位；其两个附加参数未用，本课传 `0`；别的消息不一定如此 |
| `pywintypes.error` | Windows 异常类型；常见字段 `winerror`、`funcname`、`strerror` | 保留错误码、API、说明和完整回溯；不吞错后打印成功 |

消息参数中的零与目标句柄的零不是一回事。原生接口中空 HWND、广播 HWND 有特殊语义，本课绝不把 `0`、`None`、广播常量或历史数字当测试目标。`IsWindow` 到投递间窗口仍可能改变，查询/投递异常均要停止本轮，不重试到“总会成功”。

较低完整性等级向更高等级目标投递可能受 UIPI 限制，错误 5 需结合 API/环境判断。软件预期管理员启动，开发时由用户在已提升终端运行并核对实际权限；先用明确普通测试目标，失败不自动强杀。窗口消失也不证明进程退出；管理员不保证任何目标都可操作。

## 9. 技术面试与参考答案

题目与对应参考答案放在一起，可自主阅读、复述或按需分次复习，无需逐题回复。看过答案与能独立解释分别记录。

### 1. HWND、一般句柄、指针、PID、坐标和标题各是什么？为什么保存一个句柄整数不等于保住那个窗口，或得到访问目标内存的权利？

**参考答案**：HWND 按窗口 API 契约引用窗口，一般 HANDLE 是其他多种 Windows 接口采用的句柄类型；指针表达某地址空间的内存位置。它们的底层表示不赋予调用者任意解引用权利，Python 整数只是包装形式。PID 标识进程，一个进程可有多个窗口；坐标是位置，标题是可变属性。窗口销毁后句柄失效或复用，保存数值不会延长生命周期。项目不能据数字巧合长期锁定目标，也不能把 HWND 当别类资源释放或当内存地址使用。

### 2. 为什么同时记录命中与根窗口？`GA_ROOT=2`、`GA_ROOTOWNER`、等待 `3` 秒分别来自什么约定，改变它们影响的是关系还是时间？

**参考答案**：点可能命中子窗口，GA_ROOT 沿父链取根；GA_ROOTOWNER 还考虑 owner，可能到另一顶层对象，不能因名字更完整就替换。`2` 是关系选择常量，无时间单位，不是走两层；`3` 秒是给人移动鼠标的操作时间，可按体验改。主屏原点和客户区原点也不同，不能混传坐标。项目保存命中/根各自信息核对目标，不能强求同窗不同区域一定给出不同句柄。

### 3. 解释本脚本关键 API 的输入/返回：`WindowFromPoint` 为何传一个元组，Python 与 C 签名为何不同？空句柄、空标题和查询异常如何区别？

**参考答案**：GetCursorPos 无参读当前屏幕点；WindowFromPoint 的 Python 包装把一个两整数元组转换成原生点结构，返回 HWND。GetAncestor 以 HWND 和标志返回根；标题/类名查询接收各自 HWND 返回字符串。包装还处理了部分缓冲区与转换，不能照搬 C 参数数量。空句柄使后续没有可查询对象，空标题可能正常，异常则是调用失败要保留原因和时序。不能异常后拼旧结果，也不能因属性为空直接认证桌面。

### 4. 若同窗两处命中相同，或屏幕点相同但移窗后对象改变，你怎样设计一个单因素实验、预测结果并解释？连续查询期间窗口消失时，当前检查能保证什么、不能保证什么？

**参考答案**：先固定对象、区域和采样时机，只改变一个条件并写预测，再保存原始点、命中/根及属性。自绘元素可能没有独立子 HWND，所以相同命中不一定错；移窗或遮挡改变该点当前覆盖对象，点与窗口并非固定绑定。屏幕空间/缩放问题先记录环境，不猜比例。空句柄检查只覆盖查到空值，窗口仍可在下一调用前销毁；现存脚本的连续查询不构成原子快照，异常路径尚待复验，不能声称已修复。修改由本人完成并做正常/失败回归。

### 5. 怎样同时证明本课工程与学习成果，说明独立贡献并接到未来 GUI？源码/语法通过、实测、能讲解、commit 与 push 分别说明什么？

**参考答案**：工程证据是可运行识别、原始测试和必要修复/实际版本记录；学习证据是五层解释、本人设计实验、参数/流程分析和真实问题/边界推理。语法检查只证明可解析，实测只覆盖条件，能独立应用并讲解才补齐掌握证据。参考过答案要如实说明，不因相同文件推断作者或假装独立。commit 是本地版本、push 是远程同步，都不自动证明功能。识别能力未来接在“开始→点选”之后、过滤之前，GUI/关闭/输入/发布仍需开发，不能把本脚本当成品。
