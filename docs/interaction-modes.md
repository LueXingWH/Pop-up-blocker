# 普通/强制模式、管理员启动与持续清理契约

更新：2026-10-27（Asia/Shanghai）。用户确认双模式、管理员权限启动及右键持续清理；这是需求与设计记录，相关功能尚未实现/验证。当前进度仍由 [总体计划](development-plan.md) 维护，核心实现和接线由用户独立完成。

## 1. 产品行为

| 项目 | 普通模式 | 强制模式 |
|---|---|---|
| 作用对象 | 当次选中并通过过滤的窗口 HWND | 当次窗口所属、已核对并通过过滤的单个进程 |
| 操作 | 投递 WM_CLOSE 正常关闭请求 | 使用进程终止接口发起强制终止 |
| 保存/确认 | 由目标软件自行决定，可用左键操作或取消 | 不走正常关窗保存流程；未保存内容可能丢失，不保证目标退出清理 |
| 多窗口影响 | 取决于目标软件如何处理该窗口关闭请求 | 同进程的多个窗口可能一起消失；多进程应用可能仍有其他进程运行 |
| 反馈 | “已发送关闭请求”与实际窗口观察分别记录 | “已发起进程终止”与“已确认进程退出”分别记录；不能仅凭窗口消失推断整个应用退出 |
| 失败 | 显示拒绝/错误，不自动升级强制模式 | 显示拒绝/错误，不绕过系统保护、不按名字批量重试 |

两种策略都以管理员权限启动；“普通”指正常关窗策略，不指普通用户权限。实现约定为默认普通模式，强制模式显式选择；强制模式旁常显“可能结束同进程多个窗口，未保存内容可能丢失”。不增加每次右键都弹工具确认框的要求。

空闲时选择策略，再点击“开始清理”。清理会话固定开始时的策略，期间禁用切换；需要切换时先 Esc 退出。这样可避免旧事件排队后被解释成另一种操作，事件仍需带会话与操作身份，不能仅依赖按钮禁用。

| 输入/状态 | 约定 |
|---|---|
| 开始清理 | 进入持续清理会话，改变光标，显示当前策略及“右键清理 · 左键正常操作 · Esc 退出” |
| 右键一次完整动作 | 识别并过滤目标，最多执行当前策略一次；选择性消费右键按下/松开，避免附带右键菜单 |
| 左键 | 正常放行，可点击确认框、切换窗口等；不触发工具清理 |
| 操作完成/拒绝/目标变化/可恢复失败 | 反馈本次结果，保持会话；不拿上一次目标补齐失败数据，不自动重试 |
| Esc | 停止接纳新动作，拒绝尚未接纳执行的旧事件，完成必要输入配对，恢复光标与正常输入 |
| 致命异常/程序退出 | 收尾自身监听、等待任务与句柄，恢复输入/光标，记录失败 |

Esc 不能撤销已经投递的 WM_CLOSE 或已经发起的进程终止。单次操作完成不等于会话结束；等待结果不能阻止继续响应输入与退出。对同一进程仍在处理的重复终止动作须去重，不靠连续右键或自动循环重复终止。

## 2. 权限、目标身份与范围

软件预期经 UAC 请求管理员权限；取消授权则不启动清理，不静默把“普通策略”等同未提权运行。开发阶段在用户自行打开的管理员终端中运行项目解释器，并核对实际权限；终端标题、账户属于管理员组、安装器曾提权都不能单独证明应用进程已提升。

管理员权限不等于任意进程都可终止。访问权、受保护进程和系统限制仍须处理；本项目不扩展为系统保护绕过、调试特权提升或进程树清理工具。[Microsoft 进程访问权](https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights)

两种模式均过滤自身、桌面、任务栏和不可靠目标。强制模式须把过滤扩展到所属进程，拒绝外壳、系统关键/受保护和身份不明对象；不能只靠窗口标题或“不在几个类名里”就允许终止。系统/外壳拒绝测试先做只读判定，禁止通过实际结束这些进程验证过滤。

HWND 标识窗口，PID 标识进程，打开的进程 HANDLE 引用进程对象；三者不能互换。窗口/PID 会失效或复用，检查也不是原子锁。由用户设计执行前的身份重核对、当次句柄持有与释放；变化或无法确认就拒绝当前操作，不能隔一段时间按旧 PID 重新打开再终止。普通模式仍只操作当次 HWND；强制模式只针对该窗口所属的已核对单进程，不按同名程序批量结束，不默认递归结束子进程。

## 3. 机制与接口速查（独立契约，不是核心实现）

继续采用 pywin32，不新增进程管理依赖。普通模式复用 [Day03](../lessons/Day03_2026-10-26_学习流程.md) 的窗口消息教材。强制模式增加进程对象、访问权与生命周期学习；直接绑定 ctypes 是备选，当前没有证据要求另写重复封装。以下只列独立接口，不提供可复制的完整执行链。

| 模块/调用 | 参数、返回/错误与职责 |
|---|---|
| `win32gui.PostMessage(hwnd, win32con.WM_CLOSE, 0, 0)` | 普通模式；两个零来自 WM_CLOSE 的未使用附加参数。pywin32 包装成功返回 None，失败抛 Windows 异常；成功只表示投递 |
| `win32process.GetWindowThreadProcessId(hwnd)` | 返回 `(thread_id, process_id)`；第二项才是 PID，不是返回进程句柄 |
| `win32api.OpenProcess(access, False, pid)` | 返回 PyHANDLE；access 为所需访问权组合，False 表示不允许子进程继承句柄。失败保留 `pywintypes.error`；不是传 HWND |
| `win32con.PROCESS_TERMINATE` / `win32con.SYNCHRONIZE` | 分别是终止权与等待同步权，按实际需要组合；额外身份查询权按最终所用接口核对，不默认索取 PROCESS_ALL_ACCESS |
| `win32api.TerminateProcess(process_handle, exit_code)` | 需要终止权；exit_code 是应用约定的无符号退出状态，不是 PID/消息号/等待时长，具体值由实现说明。调用他进程的终止操作是异步发起，正常返回不证明退出完成；失败保留原 API、错误码与文本 |
| `win32event.WaitForSingleObject(process_handle, milliseconds)` | 需要等待权；超时单位毫秒，返回等待状态。进程对象已发信号对应 WAIT_OBJECT_0，WAIT_TIMEOUT 表示本次仍未确认；失败保留异常。不得在输入回调/GUI 主线程无限等待，超时也不自动重发终止 |
| `process_handle.Close()` | 释放自己持有的 PyHANDLE；关闭句柄本身不终止目标。正常/异常/超时收尾均须覆盖，不对别人的 HWND 调句柄释放接口 |

安装名均为 `pywin32`；`win32api`、`win32process`、`win32event`、`win32con` 和 `pywintypes` 是导入模块，不分别 pip 安装。当前只核对维护者契约，尚未在本项目执行强制模式。C API 的 BOOL 不能未经核对就套作 Python 包装返回判断。[OpenProcess 包装](https://mhammond.github.io/pywin32/win32api__OpenProcess_meth.html)、[TerminateProcess 包装](https://mhammond.github.io/pywin32/win32api__TerminateProcess_meth.html)、[等待包装](https://mhammond.github.io/pywin32/win32event__WaitForSingleObject_meth.html)、[PyHANDLE](https://mhammond.github.io/pywin32/PyHANDLE.html)

理解重点：普通模式走目标消息处理，目标可拒绝；强制模式由系统终止该进程的线程，不保证正常保存与清理。外部终止调用先返回，再以进程对象的等待状态确认退出；释放本工具持有的句柄与目标退出是两件事。[Microsoft TerminateProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess)
