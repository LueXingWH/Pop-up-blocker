## 1. 交付目标、边界与预算

**同等重要的两个目标：按期独立交付软件，真正学会关键新技术；共同要求是能够证明。** 在 **2026-11-06 DDL 前**交付具有 GUI、可独立运行、可安装和卸载的 Windows 软件，同时能解释所用机制、参数、代码、取舍与排障。11-05 形成候选版并复盘，11-06 只验收、必要修复和提交。沿用源码、环境和 Git 历史，不重开项目。

从 10-27 至 11-06 共 11 个每日 100 分钟时段，预算 1100 分钟（18 小时 20 分钟）；最后 100 分钟留给交付核验与已学知识复盘。常规日默认 **30 分钟新技术/原理＋50 分钟独立编码实验调试＋10 分钟测试＋10 分钟技术总结/Git/面试复盘**；也可 **25＋55＋10＋10**，前两段联动，不加成 105 分钟。理论不退化为浏览链接，实验不被长篇讲授吞掉；已证实会的内容不重复。该预算不是已投入时长，最后交付日不硬塞新技术。

不能以“用了一个 API”当学习成果，也不能以“概念答得好”代替独立应用。每项关键技术按“是什么、为什么、怎么工作、怎么使用、怎么应用与改进”五层学习，以“理解原理→独立编写→实际测试→排查问题→能够讲解”验收。使用封装可以，但须解释对应 Windows/Qt 机制、封装边界和生命周期；不要求为了深度重写全部底层实现。

用户列出的优先级沿用并纳入 10-27 新需求：P0 为普通/强制双模式、管理员启动、稳定 GUI、可运行程序、安装包；P1 为异常/状态提示、取消体验和基础美化的完善；P2 为托盘、额外快捷键、动画和高级设置。**最低取消、目标过滤、句柄/权限错误处理、状态复位、选择光标及恢复已列入 MVP，属于 P0 可用性的前置，不等到增强阶段才补。**

**2026-10-27 用户确认的 MVP 变更**：软件预期以管理员权限启动，提供普通/强制双模式。普通模式对窗口投递 WM_CLOSE；强制模式终止选中窗口所属的已核对、允许操作的单个进程，可能同时影响同进程多个窗口并丢失未保存内容，不代表结束整个应用进程树。默认普通，强制显式选择；普通失败不自动升级。具体机制、API、权限及验收统一见 [双模式契约](interaction-modes.md)。两种策略都点击“开始清理”进入持续会话并改变光标，右键逐个处理目标，左键正常操作，Esc 退出恢复。双模式/持续清理属于 MVP；任务栏图标映射仍不纳入 DDL。

设计理由：用户需要连续清理，并自主选择保留正常关闭流程或强制结束进程。只选择性拦截右键/退出操作，正确配对，左键正常放行；普通模式可左键处理目标确认框，强制模式不承诺保存流程。空闲时切换策略，开始时固定本会话策略并拒绝旧事件；每次有效右键最多执行一次当前策略，拒绝/可恢复失败后继续。致命异常/退出须恢复输入与光标。管理员权限不是受保护进程可操作的保证；强制分支补进程级过滤、身份核对、句柄释放与退出确认，不按名字批量结束/递归杀进程树。相关代码尚未编写、交互及管理员启动未实测；确认框问题仍是设计风险，不记为已修复 Bug。旧“全局禁止强制”规则改为“普通模式不自动升级”，旧输入规则由持续会话约定替代。

待验收：两种策略的连续目标、模式固定/旧事件、左键透传、右键配对、Esc 恢复、重复进入/退出；普通模式确认框/取消与不自动升级；强制模式同进程多窗口影响、进程身份/过滤、最小访问权/句柄释放、超时/退出确认；目标失效/权限失败、管理员启动的 UAC 同意/取消、安装器与应用权限分别核对。完整场景见双模式契约，全部待测。
