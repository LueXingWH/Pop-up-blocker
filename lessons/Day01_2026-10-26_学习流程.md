## 4. B：接口、坐标与时间边界

你已有算法题 Python 基础；现有脚本也使用了解包。本课不重复导入语法、赋值、打印或下标。没有必须新学的 Python 语法；出现具体问题再按需补齐。

### B1. 理解调用层与接口契约

安装包是 pywin32，模块是 `win32gui`，具体函数是 `GetCursorPos`。它把 Windows 的原生能力包装成 Python 调用；PySide6 在之后负责我们自己的界面。包名和模块名不一定相同。

调用形式为 **`win32gui.GetCursorPos()`**，不传参数，因为读取的是系统当前光标位置；返回两个整数的屏幕坐标元组 `(x, y)`。原生 C 接口需要输出指针、返回成功标志，Python 包装直接给坐标；按包装签名调用，不照抄 C 的参数。[维护者接口](https://mhammond.github.io/pywin32/win32gui__GetCursorPos_meth.html)、[微软接口](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getcursorpos)

### B2. 屏幕坐标与采样时机

主显示器左上角是 `(0, 0)`，向右 x 增大，向下 y 增大；多屏布局允许负坐标。这不是窗口客户区相对坐标。后续与 Qt 或截图结合时需核对坐标空间、DPI 约定，不凭缩放百分比自行修正。[虚拟屏幕](https://learn.microsoft.com/en-us/windows/win32/gdi/the-virtual-screen)

一次调用取得的是该时刻的快照，保存后的元组不会跟随鼠标移动。重复显示旧结果与重新调用 API 是两种不同实验。

等待工具为标准库 `time` 的 **`time.sleep(seconds)`**：非负秒数，可为小数，正常返回 `None`；暂停当前线程，实际时长可能更长。3 秒是为操作者移动鼠标选择的经验值，不是坐标 API 参数。以后在 GUI 线程直接等待可能妨碍界面响应，届时再学调度。[Python 说明](https://docs.python.org/3/library/time.html#time.sleep)

### B3. 无关核心的短例子：记录与重新观察

```python
inventory = {"stock": 12}
```

4. 怎样证明两个数表示屏幕坐标？一次单屏成功为什么不能覆盖所有显示器与缩放条件？

## 7. 常见错误：先照这里查

| 现象 | 优先检查与处理 |
|---|---|
| 找不到 `py` | 试 `python --version`；两者都失败则处理安装或路径，不继续猜命令 |
| 找不到 `.venv\Scripts\python.exe` | 当前终端是否在项目目录？虚拟环境创建是否成功？用 `dir` 查看目录 |
| `No module named 'win32gui'` | 检查编辑器实际使用的 Python 路径。项目库装在 `.venv` 时，另一个 Python 会找不到它；从项目根目录运行 `.\.venv\Scripts\python.exe .\lessons\practice_day01.py` |
| 找不到练习文件 | 当前使用已有的 `lessons/practice_day01.py`；核对运行路径与实际保存路径，不必另建相同实验 |
| 找不到函数或循环导入 | 文件不要命名成 `win32gui.py`、`math.py`、`time.py`，避免遮住库；同时检查拼写 |
| 坐标看上去没变 | 函数只在调用那一刻取值；检查有没有重新调用，等待是否放在调用前 |
| 下载依赖失败 | 保存完整报错，区分网络问题与版本兼容问题；不要随意从陌生站点下载文件 |
| `No matching distribution found` / `Could not find a version` | 先检查包名，再看 Python 版本、位数及该包的平台支持；记录完整输出，不反复盲装 |
| `DLL load failed` | 先确认解释器和包位于同一项目环境，查看版本/位数，再保存完整报错分析；不要从陌生网站补 DLL |
| PowerShell 提示脚本禁止运行 | 本单直接调用 `python.exe`，无需运行 `Activate.ps1`，不必为此改系统执行策略 |

统一排查顺序：当前目录与文件名 → 解释器路径/版本/位数 → 同一环境的 pip 与包位置 → 导入检查 → 自己代码及报错行 → 移动对照与调用时机。每次改一个已定位的问题，再重新验证。

求助格式：预期发生什么 + 实际发生什么 + 自己的代码 + 完整报错 + 已尝试什么。你可以在阅读报错时先看最后一行，再看报错指出的文件与行号。
