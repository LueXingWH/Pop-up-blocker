## 2. 先建立窗口识别的模型

### 屏幕坐标与采样时机

`GetCursorPos()` 返回屏幕坐标 `(x, y)`，主显示器左上角为原点，向右、向下分别增大。多屏布局中，主屏左侧或上方可能出现负数。它不是窗口客户区内部的相对位置。

今天将该屏幕坐标原样交给接受屏幕点的 `WindowFromPoint`，在同一脚本和相同环境下验证。涉及 Qt、截图或混合 DPI 显示器时要重新核对坐标约定，不凭“系统缩放 150%”自行乘除。未测试的显示器或缩放组合写明未验证。依据：[GetCursorPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getcursorpos)、[虚拟屏幕](https://learn.microsoft.com/en-us/windows/win32/gdi/the-virtual-screen)。

坐标只是快照。等待是给人移动鼠标的时间；`time.sleep(seconds)` 的单位是秒，允许非负小数，正常返回 `None`，会暂停当前线程，实际暂停可能更久。`3` 秒是可调整的操作时间，不是 Windows 协议要求，也不是监听频率。GUI 阶段会重新设计调度方式。[Python 说明](https://docs.python.org/3/library/time.html#time.sleep)

采样位置之后，如果窗口移动、关闭或被另一个窗口覆盖，后续查询面对的是改变后的桌面。因此记录原始坐标，并尽量让同一条观察的查询紧邻发生；多次调用没有自动形成原子快照。今天仍只做单次实验，点击时刻坐标留给监听课程。

### HWND、标题和类名各自表示什么

HWND 是系统引用一个窗口的句柄，在今天的包装中以整数形式使用；不是进程 ID、窗口标题或坐标。无需推算它的数值，也不把它长期写死：窗口销毁后，旧数值可能失效或被复用。

标题是可能变化、重复或为空的显示文字；类名是 Windows 窗口类的名称，不是 Python 类名，也不是唯一窗口标识。二者适合诊断与对照，不能单独证明“这是允许关闭的目标”。

### 命中控件与命中整个窗口

Windows 界面可能包含父窗口和有独立句柄的子窗口，例如某些编辑区或按钮；也有界面元素完全由应用自己绘制，没有独立 HWND。不能要求每个视觉控件都返回不同句柄。

`WindowFromPoint` 查询指定点处的窗口，结果可能是子窗口。`GetAncestor` 配合 `GA_ROOT` 沿父窗口关系找到根窗口；若输入本来就是根窗口，结果可与输入相同。这样可以比较“鼠标碰到的局部对象”和“其所属的顶层窗口”。[Windows 窗口关系](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features)

父子关系（parent）与所有者关系（owner）不同。对话框可以是有 owner 的顶层窗口。今天选 `GA_ROOT`，研究父子归属；`GA_ROOTOWNER` 还会沿 owner 关系查找，可能走到另一个顶层窗口。不要因为它名字更长就认为更合适。这是本课实验选择，尚不是最终关窗策略。[GetAncestor 契约](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getancestor)

## 3. 接口表：准确用法和边界

下面是各接口的独立调用形式，变量名表示输入含义；流程组织由你完成。

| 调用形式 | 参数与返回值 | 调用时机及用途 |
|---|---|---|
| `win32gui.GetCursorPos()` | 无参数；返回两个整数的屏幕坐标元组 | 操作者移动完成后采样一次 |
| `win32gui.WindowFromPoint(point)` | `point` 是一个 `(x, y)` 整数元组，作为一个参数传入；返回窗口句柄 | 对该次采样点查询直接命中的窗口 |
| `win32gui.GetAncestor(hwnd, win32con.GA_ROOT)` | `hwnd` 是待查窗口句柄；标志选择沿父链找根；返回根句柄 | 已拿到命中句柄后研究顶层归属 |
| `win32gui.GetWindowText(hwnd)` | 一个窗口句柄；返回 Python 字符串 | 读取要比较的命中窗口或根窗口的文本，顶层普通窗口通常为标题 |
| `win32gui.GetClassName(hwnd)` | 一个窗口句柄；返回 Python 字符串 | 为对应窗口补充类名，帮助诊断层级与差异 |

参数中的 `GA_ROOT = 2` 来自 Windows API 契约，是枚举选择值，没有秒或像素单位；代码用常量名表达意图。它不是层数、循环次数或你调出来的经验阈值。

必须知道的返回边界：

- 原生 `WindowFromPoint` 未命中返回 NULL，Python 包装的空句柄可表现为 `0`；查不到有效目标时，保留结果并停止本轮后续信息查询，不把 `0` 当作正常窗口。它不返回隐藏或禁用窗口；静态文本控件还存在特殊命中规则，详见[微软说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-windowfrompoint)。
- 原生 `GetAncestor` 失败返回 NULL；包装调用也可能因失败抛出异常。遇到空句柄或异常，分别记录失败的调用与输入，不能继续用旧结果拼出一条“成功”记录。桌面窗口作为输入时存在返回 NULL 的规定。
- `GetWindowText` 返回空字符串不足以证明识别失败，也不足以证明命中了桌面。跨进程读取标题与读取控件内部文本能力不同，它不是通用“读取界面所有文字”的工具。[原生 GetWindowText](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowtextw)
- `GetClassName` 用于查询窗口类；调用失败时保留原始报错，不能把读取不到类名解释为“这是可以关闭的普通窗口”。[原生 GetClassName](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclassnamew)
- 窗口可能在查询之间消失。先用稳定的普通窗口实验；若遇到异常，把完整回溯和当时操作留下，不以捕获所有异常再忽略来掩盖它。今天无需提前实现通用重试框架。

Microsoft 文档展示 C 接口，包含输出缓冲区、指针或字符数；pywin32 管理了部分转换，本表采用 Python 包装的签名。不能照抄 C 参数个数。例如 Python `GetWindowText(hwnd)` 直接返回字符串，不需要你提供缓冲区。

维护者接口依据：[GetCursorPos](https://mhammond.github.io/pywin32/win32gui__GetCursorPos_meth.html)、[WindowFromPoint](https://mhammond.github.io/pywin32/win32gui__WindowFromPoint_meth.html)、[GetAncestor](https://mhammond.github.io/pywin32/win32gui__GetAncestor_meth.html)、[GetWindowText](https://mhammond.github.io/pywin32/win32gui__GetWindowText_meth.html)、[GetClassName](https://mhammond.github.io/pywin32/win32gui__GetClassName_meth.html)。所需用法已在正文讲清，链接是可选参考。

## 4. 短例子：观察值与唯一身份

这个例子用虚构的传感器记录演示“数值相同不足以证明是同一个对象”，与窗口识别实现无关；没有新语法要背。

```python
first = {"sensor": "A", "reading": 24}
second = {"sensor": "B", "reading": 24}
print(first["reading"] == second["reading"])
print(first["sensor"] == second["sensor"])
```

预期输出 `True`、`False`。第一步比较观测属性，第二步比较这个虚构系统约定的设备标识；二者回答的问题不同。修改练习：让 A 的读数变成 25，说明它是否因此变成了另一台设备。

对应到今天：标题是观察属性，不能用“两个标题相同”推出“同一个窗口”；同一次稳定实验中可以比较句柄，但窗口生命周期结束后，句柄数值也不能充当永久身份。

## 7. 调试顺序与常见问题

顺序：运行路径和解释器 → 输入的坐标/句柄类型 → 直接命中 → 根窗口 → 标题/类名 → 时序及桌面变化。一次只验证一个假设。

| 现象 | 优先核对 |
|---|---|
| 导入失败 | 是否用了项目 `.venv`；库装在另一解释器不能证明本环境可用 |
| `WindowFromPoint` 参数错误 | Python 包装接收一个元组，不是两个独立位置参数；对照接口表 |
| 总是识别终端或编辑器 | 采样前鼠标是否已移走；目标是否被遮住；是否读取太早 |
| 标题为空 | 同时看句柄、类名和根窗口，区分控件/无标题/读取限制，不能只凭空字符串下结论 |
| A、B 两个窗口根句柄相同 | 是否选中了同一个实际顶层对象；输出标签或变量是否混用；窗口是否遮挡 |
| 同一窗口命中句柄一直相同 | 该界面可能没有独立子窗口；这是观察结果，不应为了“符合教材”改值 |
| 某次失败或窗口已消失 | 保留报错调用、输入句柄、操作顺序；用稳定窗口复现，考虑调用之间的状态变化 |
| 函数不存在或模块来源异常 | 检查拼写和包版本；脚本不要命名成 `win32gui.py`、`win32con.py` 或 `time.py` |
| 只有另一屏/缩放环境有偏差 | 记录屏幕布局、缩放和复现位置；回到坐标约定定位，暂不猜测比例修正 |

合格标准：能说明设计理由、参数来源、至少一个失败路径与验证边界。未比较过的方案可以提出假设，不声称已经证明优劣。

## 9. Git 收尾：由你操作 GUI

当前本目录尚未成为 Git 仓库，首次设置可参考 [Day01 的 G 节](Day01_2026-10-26_学习流程.md)。在 Git GUI 中确认仓库路径是 `D:\技术组项目`；若没有本地仓库，创建在这里，避免误选 `.venv` 或另一个空目录。远程地址使用你实际创建的 GitHub 仓库地址，不猜填。

首次暂存前，自己创建项目根目录 `.gitignore`，至少包含：

```gitignore
.venv/
__pycache__/
*.pyc
build/
dist/
```

核对 GUI 待提交列表没有虚拟环境、缓存或打包产物，再选择源码、学习单、计划和项目约定。不要忽略整个 `lessons`。如果生成物已经被跟踪，增加忽略规则不会让它自动退出历史或暂存，先保留现场并针对性处理。

检查差异 → 暂存选定文件 → 本地 commit → push → GitHub 网页核对提交标识。commit 保存本地版本，push 才同步到远程。提交信息按实际完成写，例如只写了文档就说明文档变化；实验未通过不能声称通过。AI 不替你提交或推送。

如果首次设置占满收尾时间，保存报错与停点，Git 状态记为未完成；没有修改就不制造空提交。[GitHub 忽略规则](https://docs.github.com/en/get-started/git-basics/ignoring-files)
