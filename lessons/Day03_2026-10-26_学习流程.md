## 2. 原理：Windows 消息为什么能表达关闭意图

窗口不是一个可以直接“删掉”的 Python 对象。你的程序与目标程序属于各自的进程；Windows 为窗口提供消息处理机制。`WM_CLOSE` 是系统约定的一类消息，目标收到后有机会决定如何响应。处理它的程序可以先询问是否保存，再决定销毁窗口；不能由发送端保证一定出现提示或一定关闭。[Microsoft：WM_CLOSE](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-close)

`PostMessage` 的工作像投递通知：本次调用成功表示投递环节成功，不表示收件人已处理。目标忙碌、忽略消息或等待用户选择时，窗口都可能还在。因此实验记录至少分开写“调用是否报错”和“我看到什么”。[Microsoft：PostMessage](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew)

这里选异步投递，是为了发起正常请求时不等待目标处理结束。同步 `SendMessage` 会等待目标窗口过程处理，可能带来等待问题；本课无需实现或比较所有替代方案，不声称它在所有场景都更差。

关闭窗口与结束进程也不同：同一进程可能有多个窗口，程序还可能常驻后台。本课不调用结束进程、强制销毁其他程序窗口的接口，也不在请求失败时升级为强杀。目标程序自己如何处理未保存内容，是观察与记录对象。

另外，`win32gui.CloseWindow` 的名字容易误导：Windows 的这个 API 用于最小化窗口，并不是这里要学习的正常关闭请求。[Microsoft：CloseWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-closewindow)

## 3. 接口说明：先知道工具，再独立组织

下面各行是独立调用形式，不是可复制的完整关窗流程。`hwnd` 等名称表示你要传入的数据；先核对输入含义，再使用自己的变量。

| 调用形式 | 参数、单位、返回值 | 用途与时机 |
|---|---|---|
| `win32gui.PostMessage(hwnd, message, wparam, lparam)` | `hwnd` 为目标句柄；`message` 为消息编号；后两项含义由消息定义。本包装成功返回 `None`，失败抛出 Windows 异常 | 仅在确认当前测试目标后投递一次。它不返回目标是否已经关闭 |
| `win32con.WM_CLOSE` | 命名常量，值为 `0x0010` / `16`，无时间或像素单位 | 作为上行的消息编号；不是等待时长，不随意改数字 |
| `win32gui.IsWindow(hwnd)` | 一个句柄；返回非零/零，可按真/假判断 | 查询此刻句柄是否仍指向现存窗口；不锁住目标，不保证下一次调用时仍有效 |
| `win32gui.GetWindowText(hwnd)` | 一个句柄；返回字符串，可能为空 | 确认前重看目标信息；标题不是唯一身份 |
| `win32gui.GetClassName(hwnd)` | 一个句柄；返回类名字符串 | 和 Day02 信息一起核对目标；类名不单独证明可以关闭 |
| `input(prompt)` | 提示字符串；暂停当前终端线程，返回你输入的字符串 | 本课给人一次明确确认机会；不要放在未来输入回调或 GUI 线程中 |
| `time.sleep(seconds)` | 非负秒数，正常返回 `None` | 如沿用 Day02，给人移动鼠标的时间；不是等待关窗成功的可靠方法 |

`WM_CLOSE` 的 `wParam`、`lParam` 均未使用，本课二者传 `0`。这两个零来自该消息契约；不能推广为“所有 Windows 消息都传零”。与句柄位置传 `0` 完全是两回事。

**句柄参数不可用 `0`、`None`、广播常量或旧记录中的数值代替。** 原生 `PostMessage` 对空句柄和广播句柄有特殊含义，并非“什么都不做”；本课只对当次已确认的单个测试窗口实验。

尤其注意 Python 与 C 文档的差异：C 的 `PostMessageW` 返回 BOOL；pywin32 将这里的成功映射为 `None`、失败映射为异常。因此不能用“Python 返回值为假”判为失败，也不能把 `WM_CLOSE` 接收方的返回值当作发送函数的返回值。依据：[包装签名](https://mhammond.github.io/pywin32/win32gui__PostMessage_meth.html)、[维护者 BOOLAPI 转换定义](https://github.com/mhammond/pywin32/blob/main/SWIG/swig_lib/python/pywintypes.i)、[绑定声明](https://github.com/mhammond/pywin32/blob/main/win32/src/win32gui.i)。

`IsWindow` 是观察，不是长期有效证明：窗口可以在检查后消失，句柄数值也可能被系统复用。确认后若目标关闭、重建或身份信息改变，应放弃本轮并重新识别；不能无限重复发送。即便紧邻核对，也不把跨进程的多次调用称为原子操作。[Microsoft：IsWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-iswindow)

权限边界：Windows 的 UIPI 会限制普通权限程序向更高完整性级别程序投递消息，可能出现错误码 5（拒绝访问）。本课先用同权限普通测试窗口；遇到权限失败保留错误，不以管理员运行作为默认解决方式。

## 4. 今天的 Python：精确捕获异常，保留原因

你已有基础语法，不重复练赋值、循环或元组。今天重点补齐 `try / except / finally`：`try` 内出现匹配异常时跳到 `except`；`as` 给异常对象取本地名字；`finally` 在正常返回或异常退出时都用于收尾。它不能保证断电或强制终止进程时执行。

与窗口核心无关的短例子：

```python
raw = "两杯"
try:
    cups = int(raw)
    print("杯数：", cups)
except ValueError as error:
    print("输入不是整数：", type(error).__name__)
finally:
    print("本次检查结束")
```

逐步看：`int` 无法把“两杯”转成整数，抛出 `ValueError`，所以“杯数”不打印；匹配的 `except` 显示异常类型，最后仍打印收尾文字。

预期输出：

```text
输入不是整数： ValueError
本次检查结束
```

修改练习：把 `raw` 改为 `"2"`，先预测再运行；解释为什么 `except` 不执行、`finally` 仍执行。可在自己的练习草稿测试，不必加入关窗文件。

在 Windows 实验中，异常类型用 `pywintypes.error`，不是上例的 `ValueError`。对这类异常，`error.winerror` 是错误码，`error.funcname` 是 API 名，`error.strerror` 是说明；完整打印异常也能保留关键信息。导师给的是异常工具用法，具体在哪捕获、如何终止本轮由你设计。不要用不分类型的捕获配合 `pass` 隐藏失败。[Python：异常](https://docs.python.org/zh-cn/3/tutorial/errors.html)

## 7. 常见错误与排查顺序

固定顺序：解释器与导入 → 本次目标与层级 → 确认是否有效 → 消息和参数 → 包装异常 → 目标的实际行为。

| 现象 | 优先核对 |
|---|---|
| 提示 `ModuleNotFoundError` | 是否用项目 `.venv`，安装名与导入模块名是否混淆 |
| 返回 `None`，日志却报失败 | pywin32 的成功返回约定；不要套用 C 的 BOOL 判断 |
| 日志说发送成功，窗口仍在 | 是否等待保存、软件自身策略或消息尚未处理；不要直接归因于接口失败 |
| 目标最小化了 | 是否误用了 `CloseWindow` |
| 错误 5 | 目标权限是否比本程序高；记录限制，先回同权限测试条件 |
| 无效句柄错误 | 目标是否已关闭/重建，是否使用旧数值或子窗口句柄 |
| 提示出现后连续弹出/重复请求 | 查本轮请求次数和重复调用来源，不用加长 sleep 掩盖 |
| 未保存测试没有提示 | 先比较该软件手动关闭时的行为；自动保存与会话恢复会改变观察 |
